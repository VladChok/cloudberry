# Roadmap

Cloudberry is being built as a sequence of product slices. The roadmap stays deliberately broad: each slice should prove a coherent human experience before the next one expands the system.

## 0. Foundations — DONE

- ✅ **Code Engine MVP** — shared implementation contracts and common verification across different agents.
- ✅ **Design / Code model comparison** — model maps can remain navigational projections instead of duplicated truth.
- ✅ **Journal event contract v1** — the live event-to-projection path and its basic invariants passed review.

These are focused proofs, not a claim that the complete Cloudberry product is implemented.

## 1. Newspaper — CURRENT

Build the first end-to-end product slice:

```text
JOURNALED ACTIVITY → READABLE STORY → TRUSTED CONTEXT → OPEN THREAD
```

The slice should answer three questions well: what happened, why does it matter, and where can the person continue?

## 2. Project and thread navigation — LATER

Make nested lines of work easy to locate and move through. Preserve project meaning across chats, runs, tools, and models.

## 3. Workspace — LATER

Complete the route from reading to action:

```text
NEWSPAPER → CONTEXT → WORKSPACE → ACTION
```

The workspace should show the smallest relevant context and support review, decisions, and continuation.

## 4. Multi-agent integration — LATER

Let stable roles be performed by different people or models while preserving provenance, reports, review, and human ownership of decisions.

## 5. External tools — LATER

Connect creative software, development tools, servers, and automation so their real activity can enter the Journal and lead back to action.

## 6. Living project environment — LATER

Bring the pieces together into a persistent, multi-project place where work remains understandable while the person is present or away.

Current scope and evidence are tracked in [Current proof](docs/current-proof.md). New proposals should strengthen the current slice or clearly explain why the sequence needs to change.
